# referral-program · spec (stage 2) — draft for Richard, 12/11/26

Intent: `.sdlc/referral-program/intent.md` (all product decisions final). This spec only says HOW, what is testable, and what is flagged.

## What exists today (facts the spec builds on)
- Dashboard card "הזמן חבר" (dashboard.html `renderReferral`): `referral_code = token.slice(0,8)`, share link `ishur.io/?utm_campaign=<code>`, tier from `refcred:<tok8>` (KV counter, written by `creditReferral` in worker/index.js when a payer's lead row carries `referral:<tok8>`).
- Site pricing popup (assets/popup.js): plain package → static `CFG.growLink(guests, plan)` (30 permanent Grow pages); package + design add-on → `POST /api/quote-from-site` → Make 7362541 mints a Grow link (sum + description + cField1/cField2 only; **cField3 is not mapped yet**).
- IPN (`handleGrowIpn` → `processGrowPayment`): dedupe `grow:<ref>`, `paid:<token>`, Slack 🎉 line, `creditReferral`, invoice, CRM.
- Reviews: feedback.html → raffle (OFF) → old video/Google links. raffle.js stays off.
- Admin: clients.html is one list + "ניהול אירוע" popup; no tabs yet.

## Requirements (numbered, testable)

**R1 Choice per event.** `POST /api/referral` `{token, mode:'discount'|'commission'}` saves `ref:<tok8>` = `{token, phone, name, mode, at, locked:false}`. A second call changes `mode` only while no referral record exists for the code (`locked` false); after the first referral the route answers `{ok:false, error:'locked'}`.
**R2 Code and link.** The code stays `tok8` (already in old share links). Share link is `https://ishur.io/?ref=<tok8>`. `GET /api/referral?code=` (public, rate-limited) answers `{ok, mode, name_first}` or `{ok:false}` for an unknown code; it never returns phone/token.
**R3 Site capture.** index.html (and every landing page that includes the pricing block via the same script) reads `?ref=`, validates it through R2, stores cookie `ishur_ref` (30 days, also localStorage) and keeps it across pages. The old `utm_campaign=<code>` links keep working: treated as `ref` when `utm_source=referral`.
**R4 Discount pricing.** With a valid `mode:'discount'` ref, every package price on the page shows struck full price + 80% price (rounded to whole ₪, `Math.round(p*0.8)`) + the tag "הנחת חבר של <שם פרטי>". Hostess bundles, design, add-ons: full price (20% is on the package only). With `mode:'commission'` the page shows normal prices (no tag).
**R5 Discount checkout.** The buy button for a discounted package goes to the 80% Grow page from `CFG.GROW_LINKS_REF[guests_plan]` with `?cField3=ref:<code>` appended. If the mapping entry is empty (page not yet created by Richard) or the order carries add-ons, the popup calls `/api/quote-from-site` with `ref:<code>`; the worker prices the package line at 80% and sends `cField3:'ref:<code>'` to Make (R10). Either way, before redirecting, the site POSTs `/api/ref-touch {code, phone}` so the worker holds `refpend:<phone> = code` (30 d) — the attribution does not depend on Grow echoing custom fields.
**R6 IPN attribution.** In `processGrowPayment`, after the payment is accepted (`ok`): code = `cField3` matching `ref:<tok8>` → else `refpend:<payerPhone>` → else the existing lead-row `referral:<tok8>` path. Self-referral (payer phone = referrer phone) is ignored. One attribution per payer phone, ever (`refdone:<last9>` as today). The result is a record `refrec:<code>:<ref>` = `{code, referrer_phone, friend_phone, friend_name, friend_token, sum_total, sum_package, path:'discount'|'commission', discount_given, credit, at, status:'verified', redeemed:false}`. Package sum = the package line only (quote line when structured, else `parsePaidDesc` price table lookup, else the whole sum with `note:'unstructured'`). Credit = `round(sum_package*0.2)` on the commission path, 0 on the discount path; `discount_given` = the mirror. `refcred:<code>` still increments (tier badge unchanged). `ref:<code>.locked = true`.
**R7 Credit ledger.** `credit:<referrer_phone>` = `{balance, entries:[{kind:'referral'|'review_text'|'review_video', amount, at, ref, token, redeemed_at}]}`. Review credits: ₪20 text/Google, ₪30 video, once per kind per event, added when Richard marks the claim verified in the admin tab (R12), not on the claim itself.
**R8 Dashboard card.** New card copy: choice (two radio cards "20% הנחה לחברים" / "20% עמלה לי", with the small print under commission: "העמלה נצברת כזיכוי למימוש על החבילות שלנו, לא במזומן"), code + link + copy button, buttons: WhatsApp share (text differs per mode), "ערכת שיתוף" (share.html), stats line: discount mode "חברים חסכו ₪<sum discount_given>" / commission mode "הרווחתם ₪<credit balance>", default ₪0. "למימוש" button appears when balance > 0 and opens WhatsApp to 4499 with a prefilled text (until personal-area ships). `GET /api/dashboard` adds `referral:{mode, code, link, stats:{friends, saved, earned, balance}, locked}`.
**R9 Share kit.** `share.html?t=<token>&v=discount|commission` renders on canvas, lux.css language (Frank Ruhl Libre + Heebo, gold #A8853C, pine, ivory, the ✓ mark), three sizes per variant: story 1080×1920, square 1080×1080, WhatsApp 1200×630; each carries a QR of the ref link + the link text; discount variant says "20% הנחה על כל החבילות", commission variant shows no discount. Download buttons + Web Share API on mobile. Hostesses: the repo holds NO hostess photography, so the kit uses the campaign's line-art hostess figures (gold stroke, like index.html's feature icon) — Richard can drop photos into `brand/hostesses/` later and the kit will use them (flagged, not blocking).
**R10 Make 7362541.** Map `cField3: {{1.cField3}}` in module 2 (edited via the Make MCP, verified by `scenarios_get`). `createQuoteLink` accepts `ref` and sends `cField3:'ref:<code>'`; `priceQuote` accepts `discount_pct` for the package line only.
**R11 Grow pages list.** `.sdlc/referral-program/grow-pages.md`: 30 rows (10 tiers × 3 plans): page name, title, product name, price (80%, whole ₪), success URL `https://ishur.io/thanks.html`, plus the IPN-visible description format `"<N> מוזמנים <plan> · הנחת חבר"` (test: `parsePaidDesc` still parses it). config.js `GROW_LINKS_REF` with 30 keys, empty strings until Richard pastes the links; empty → R5 minted fallback.
**R12 Admin.** clients.html gets a tab bar "לקוחות | הפניות". The הפניות tab: table referrer → friend → date → sum → path → discount/credit → redeemed (toggle), plus a second section "ביקורות ממתינות" (feedback claims: text/Google/video with "אומת ₪20/₪30" buttons). Data from `POST /api/referrals {admin_key}`; mark redeemed / verify review through `POST /api/referrals/act`. The ops home todo (hq.html / ops plan) gets one line "זיכויים ממתינים: ₪X ל-N לקוחות" when any balance > 0 and unredeemed.
**R13 Slack.** On every attributed referral payment one line: `🎉 *הפניה שילמה* · <friend> · ₪<sum> · דרך <referrer first name> · <הנחה ₪X | זיכוי ₪X>` (`IMPORTANT_RE` already matches 🎉). No alert on self/duplicate.
**R14 Reviews feed credit.** feedback.html: with raffle off and score ≥ 6, the video/Google step says "₪30 זיכוי על סרטון · ₪20 על ביקורת" and records claims `revclaim:<token>:<kind>` (existing claim endpoints reused with `kind`), no raffle text.
**R15 Noa post-event message.** The engine keeps sending `ishur_syum_v3` (feedback link) unchanged. A new utility template text `ishur_syum_credit` is written to `.sdlc/referral-program/noa-template.md` for Richard to submit to Meta; it is NOT wired until approved and Richard says "שלח". Nothing in this build sends a new message to any client or guest.
**R16 Safety.** All new client-facing routes stamped like the other site forms, rate-limited per IP; admin routes need `admin_key`. No phone/token leaks through the public code lookup. Existing tests stay green.

## Policy flags
- Live client data: the IPN path is production money flow; every new step is wrapped so a failure never blocks the payment (same pattern as `creditReferral`). Tested through `_simulated` replays only.
- PII: the public code lookup returns a first name only. Admin tab behind `admin_key`.
- Cost: no paid API; one Make run per minted link (existing scenario). KV only (no D1 migration).
- Sends: zero new automated messages. Noa template is text-only until Richard approves.
- Staging: `.sdlc/dev-staging` does not exist yet → this ships to production behind the existing test suite + smoke; the dashboard card is the only client-visible change on day one, and the discount path is inert until `GROW_LINKS_REF` is filled or a `?ref=` link is used.

## Out of scope
Cash payouts, partner redemption, raffle, personal-area login (credit redemption = WhatsApp to 4499 for now), Meta template submission, Grow page creation (Richard, from grow-pages.md).
