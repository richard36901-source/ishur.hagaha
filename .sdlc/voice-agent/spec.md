# Spec · שיר — סוכנת החיוג של ishur.io

**סטטוס: טיוטה ל-Gate 2.** נגזר מה-intent, מהמחקר המאומת (research.md)
ומההחלטות (decisions.md).

## דרישות

**V1 — הסוכנת ותשתית השיחה**
- V1.1 סוכנת Retell בשם שיר: קול נשי עברי (ElevenLabs), תמלול Soniox
  (או AssemblyAI אם Soniox לא זמין ב-Retell), LLM זול-מספיק-וטוב בעברית.
- V1.2 פתיחה: "היי, מדברת שיר מאישורי הגעה" בשם בעלי האירוע; לא
  מתנדבת שהיא AI, מודה בכנות אם נשאלת; מציעה נציג אנושי למי שמתקשה.
- V1.3 כלי mid-call יחיד `record_rsvp_outcome(outcome, party_size?)`
  עם enum מגיע/לא מגיע/מתלבט — נשלח ל-Worker בזמן אמת.
- V1.4 שיחה בעברית בלבד; משפטי הטיה נכונים (מגדר) קבועים בפרומפט.

**V2 — צנרת (Worker ↔ Retell ↔ Sheets הקיים)**
- V2.1 Worker route חדש `/api/shir-dispatch` (מוגן ADMIN_KEY, מופעל
  מתרחיש Make מתוזמן): קורא את תור "נדרשת שיחה" הקיים, מסנן לחלון
  החוקי (א'-ה' 10:00–20:30, ו' 09:30–13:00, שבת/חג חסום), מסנן
  נסיונות באותו יום (עד 3 בימים נפרדים), ויוזם create-phone-call עם
  metadata={guest_id, token} ומשתני שיחה (שם, אירוע, תאריך, מקום).
- V2.2 Worker route `/api/shir-webhook` (חתום X-Retell-Signature):
  - קריאת הכלי record_rsvp_outcome → תרגום ל-call_result הקיים.
  - call_analyzed: voicemail_reached → ניתוק, לא נספר ניסיון;
    dial_no_answer/busy → "לא ענה" (נספר); כשל הבנה → "לחייג שוב"
    ונשאר בתור של calls.html (גיבוי אנושי).
- V2.3 אפס שינוי בסכמת הגיליון; calls.html ממשיך לעבוד במקביל.

**V3 — תיעוד עלויות (הדרישה החדשה של ריצ'רד)**
- V3.1 כל שיחה: עלות אמיתית (משך × תעריף, מה-webhook) נרשמת בלוג
  "אורחים לוג הודעות יוצאות" (שורת שיחה) בעמודת עלות.
- V3.2 כל הודעת וואטסאפ: עלות לפי קטגוריית התבנית (תעריף ישראל
  העדכני) נרשמת באותו לוג על ידי מנוע השליחה.
- V3.3 מסך עלויות: עלות ממוצעת לאורח עם/בלי שיחה, עלות פר אירוע —
  נכנס לדשבורד העסקי (ראה V5).

**V4 — הטלפוניה**
- V4.1 ניוד מספר ה-SIM של ריצ'רד לספק VoIP (הזול מבין Telnyx/DIDWW
  לפי הצעות מחיר) — לפני כל רישום וואטסאפ.
- V4.2 אחרי ניוד: רישום WhatsApp Business API על המספר (תפוצה),
  חיבור SIP trunk ל-Retell (שיחות יוצאות של שיר), ניתוב שיחות
  נכנסות לטלפון האישי של ריצ'רד.

**V5 — מוכנות לקידום ממומן (out of scope לסוכנת, אבל באותו גל)**
- V5.1 קיים כבר: GA4 חי, אירועי Lead/InitiateCheckout/Purchase עם
  event_id ודדופ, תשתית Meta+TikTok pixel ב-tracking.js.
- V5.2 חסר: FB_PIXEL_ID בקונפיג (ריצ'רד יוצר Pixel בביזנס מנג'ר),
  ממסר Conversions API מה-Worker (דורש token ממטא), ודשבורד עסקי
  (משפך: ביקורים→לידים→תשלומים, עלויות, הכנסות).

## תנאי מעבר (machine-checkable)
- P1 שיחת web-demo עם שיר: ריצ'רד מדבר איתה בדפדפן, השיחה בעברית,
  והכלי record_rsvp_outcome נורה עם הערך הנכון → נבדק מול לוג Retell.
- P2 שיחת טלפון אמיתית למספר של ריצ'רד: שיר פותחת נכון, מבינה
  "אנחנו מגיעים, שניים", כותבת מגיע+2 לגיליון תוך דקה מהסיום.
- P3 תא קולי מזוהה → אין כתיבה של "לא ענה", אין שריפת ניסיון.
- P4 שיחה מחוץ לחלון (סימולציה בשעון) → dispatch מסרב לחייג.
- P5 עלות השיחה מ-P2 נרשמה בלוג בטווח ±10% מהחיוב ב-Retell.
- P6 ניסיון רביעי לאותו אורח → לא מחויג.

## דגלי מדיניות
- כסף: Retell לפי דקות — תקרת בטיחות: cap יומי של דקות ב-dispatch
  (ברירת מחדל 60 דק'/יום, ניתן לשינוי) עד שהמערכת מוכחת.
- פרטיות: תמלילים נשמרים ב-Retell; לא מוזנים ל-Sheets מעבר לתמצית.
- אין שום תוכן שיווקי בשיחות — לוגיסטיקת אירוע בלבד (חוק הספאם).
