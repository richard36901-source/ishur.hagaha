# Pay links v2 (03/11/2026)

Branch `paylink-v2` (from `integ-2026-11-02`). Nothing is deployed.

## The incident

A link with the description "100 רשומות בסיס + עיצוב הזמנה" was paid. `isDesignPayment` matched "עיצוב הזמנה", so the payment went down the design-only path and no event was created.

## API

`POST /api/pay-link` (admin). If the body has `records`, the structured path runs. Without `records`, the old free-form path `{sum, tier, plan, hostess, description, note, ...}` runs exactly as before. The playbook quick links still use it.

```json
{ "admin_key": "...", "plan": "basic|pro|premium", "records": 100,
  "addons": { "design": true, "hostesses": 2, "travel": false, "extra_wave": false, "calls": false },
  "name": "דנה כהן", "phone": "050-1234567", "occasion": "wedding", "event_date": "2026-12-20" }
```

- The server works out the sum itself (`worker/paylink.js` `priceQuote`). Any `sum` sent by the client is ignored.
- Requests are refused with 400 in these cases: `bad-plan`, `bad-records` (records must be one of 50,100…900), `bad-phone` (must be an Israeli mobile, 05XXXXXXXX or 9725…), `bad-name`, `bad-date`, `bad-hostesses`, `hostesses-unpriced` (3 hostesses), `travel-without-hostesses`.
- `calls` is never charged on pro/premium, because those plans already include a call round.
- The response is `{ok, url, id, description, sum, code, lines}`.
- The quote is stored in KV as `quote:<id>` (12 hex characters, kept 30 days) with every field and the link.
- What goes to Make (`GROW_LINK_HOOK`): `cField1 = "q:<id>|<code>"` and `cField2 = <occasion>`. The description is the human text.

### Description and code

| Item | Description piece | Code |
|---|---|---|
| package | `100 רשומות בסיס` | `pkg:basic:100` |
| design | `עיצוב הזמנה` | `design:1` |
| hostesses | `דיילת אחת` / `2 דיילות` | `host:N` |
| travel | `נסיעות דיילות` | `travel:1` |
| 3rd wave | `גל תזכורת שלישי` | `wave:1` |
| AI calls (basic only) | `שיחות AI למי שלא ענה` | `calls:1` |

Example: `100 רשומות בסיס + עיצוב הזמנה + 2 דיילות` gives `pkg:basic:100;design:1;host:2;travel:0;wave:0;calls:0`.

The wording deliberately avoids "שליחה נוספת" and "סבב שיחות". `parseAddonDesc` reads those words as an add-on to an existing event.

## IPN

- `isDesignPayment` is now true only when the payment is design-only. It returns false when the words contain a package (`\d+ רשומות|מוזמנים`) or the custom fields carry a `pkg:` code.
- `processGrowPayment` calls `purchaseOf(flat)`, which looks in this order:
  1. the `quote:<id>` row from KV;
  2. the `pkg:` code in cField1;
  3. the words (old free-form links).
- A structured purchase skips the add-on branch. The event is created by the normal path. After Make accepts it, `grantPurchaseAddons` writes the same keys the existing flows use:
  - `design:<token>` = `{status:'paid'}`, which unlocks the design brief;
  - `hostess:<token>` = `{n, date, travel_included, quote}`;
  - `extrasend:<token>`;
  - `callsaddon:<token>`;
  - `quotepaid:<id>`.
- `paid:<token>` takes its tier, plan and hostesses from the quote.
- The Slack purchase line is now `closeMessage()`: `🎉 נסגר: <name> · <phone> · <occasion> <date|תאריך טרם> · חבילה <plan> · <records> רשומות · תוספות: <list|ללא> · ₪<sum> · <dashboard> · <upload>` (plus the promo when there is one).
  - The old line's "לקוח חדש/חוזר · אסמכתא" is gone. The 💳 line before it still shows new or returning.

## Admin UI

The generator is `assets/paylink-gen.js`. It is mounted by `assets/playbook.js` in the sales section (`#pl-gen`) on admin.html and leads.html.

- The dropdowns and toggles are buttons. There are no native selects.
- The page shows a live preview total. The server's total is the one on the link.
- "צור קישור" returns the link, a copy button, and "שלח בוואטסאפ ללקוח". That button is a wa.me link with "היי, בהמשך לשיחה שלנו, זה הקישור לתשלום: <link>" and sends nothing by itself.
