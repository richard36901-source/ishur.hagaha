Switching mock → live is only the `?mock=1` flag. No other code changes. `config.js` and `guard.js` are loaded lazily in live mode only, so they don't block first paint.

Rebuild fixtures: `OPS_ADMIN_KEY=… node scripts/build-ops-fixtures.mjs`. It GETs every live endpoint once (and POSTs `toggle` WITHOUT `confirm` for each kill switch, which only returns the blast radius) and writes masked copies of the real responses. The repo is public, so it masks guest/client phones (our 6673/9799/4499 stay), replaces event names with pseudonyms, zeroes everything after the 8-char prefix of event tokens (they are board access secrets), redacts key-like fields, and hides message bodies and contact names in the live feed. `brain.json` is hand-written (no endpoint). When the live runs ledger is empty, `runs.json`/`run.json` are synthesized in the real run shape from the live feed's cron rows (`"synthetic": true`).

## Integration (03/11)

`assets/ops/adapt.js` is the only file that knows backend field names. `raw()` in `app.js` passes every response, live or mock, through `adapt(name, data, {names})`, and the screens render only adapter output. The smoke test adapts the real-shaped fixtures the same way, and its A3a block asserts the contract keys the adapter reads, so a backend rename fails the test instead of a screen.

Field mismatches fixed (fixture assumption → real API):
- realtime: no `summary` → derived (`wa_sent_today` = Σ guest `sent_today`, `wa_cap_total` = `cap.limit − cap.margin`, `wa_remaining` = `cap.remaining`, `failures_today` = `wa.totals.rejected_today + failed_async_today`, `paused` = `pacer.paused || pacer.off`). No `incidents` → derived from pacer off/paused/stale (> 25 min), `cap.wacap_guests`, `cap.all_held`, held numbers, non-GREEN quality, per-number failures by Meta code, `noa.billing_131042`, unknown numbers, Retell missing or unreadable; overview adds capacity overflow days and low balances. No `next` → `queue` (sends / calls / autoretry / event-day / late invites at `next_tick_at`). Numbers: `display/cap/queued/reasons/last_sent_at` → `tier/limit/used_24h/remaining/frees_at/held/by_reason/failed_by_code`; the scheduled/exception/failed split is computed from `by_reason` (reply + manual = exception). `wa.by_event` is per number and keyed by tok8 → merged across numbers; names come from the capacity response. `wa.recent` doesn't exist → messaging reads the live feed's `wa_out`/`wa_status` rows. Calls: `out/cap/window{from,to}/timeline` → `dialed`, `dialed + capacity_left_today`, `queue.calls.call_window.open` + `queue.calls.why`; no per-call timeline (link to calls.html); `calls:null` and `source:"retell-unreadable"` get banners.
- capacity: `date/planned_wa/capacity_wa/no_contact/events/alerts` → `day/planned/capacity/!open/by_event[type_he,count,held,upper_bound]`, alerts from `overflow`; no calls planning (calls chart hidden); recommendations `{kind: fits|move|no_window|split, day, split[], he}`; the model/verification banner and `notes` are shown.
- balances: `label/as_of/auto_topup:boolean/low by threshold` → `vendor` (label map), `checked_at` or `extra.manual_set_at`, `'on'|'off'|'unknown'`, server `status:'low'` (includes Retell's billing guard). `meta_wa` amount is month spend, Cloudflare is `requests_mtd`, `meta_ads` amount is null without a spend cap; notes come from `extra`.
- registry: `kill/severity/explain_he/stats/daypart/next_fire/code{lines}` → `kill_switch{key,wired,via}`, `risk`→P1–P3, `desc_he`, `state{enabled,off{at,by,reason},last_run_at,runs_24h,by_status_24h,next_fire}`; day-part derived from cron / IL hour of `next_fire`; no hourly sparkline or 7-day counts in the API (hidden). Code is fetched per node from `/api/ops/code?id=` when the drawer opens.
- runs: no `name/duration_ms/skip_reason`; `triggered_by` can be `parent:<id>`; the server has no `q`/`triggered_by` filter → those filter client-side. run: no `logs` → built from the run's summary/error; `audit[].summary` → `action`.
- live: `id` is a string, not increasing → sort and dedupe by `ts`; `kind/msg/level/number` → `type`+`kind`, `action`(+ short `detail`), `ok:false`/run `status`, `area` (the number filter became an area filter: שיר / נועה / שיחות / וורקר / אדמין). Key-like fields in details are redacted on screen.
- toggle: `needs_confirm/blast{impact}` → `applied:false` + `confirm_required`, `blast_radius{downstream[{name_he,fully_stopped}], messages_next_days, calls_stopped, events_affected}`.

Overview = exactly 3 requests on load: `realtime`, `capacity`, `balances` (the registry is no longer needed there). The side live panel starts 1.5 s later.

Live check: `OPS_ADMIN_KEY=… node scripts/ops-ui-live.mjs`. The Worker's CORS only allows ishur.io origins, so Playwright serves this checkout UNDER `https://ishur.io` by request interception and talks to the real API. The key goes into `localStorage.ishur_calls_key`, the same as the other admin pages. It asserts ≤ 3 requests on load, every route rendering real data, brain showing "not built yet" with exactly one 404 (no polling), the drawer loading real code, no toggle request carrying `confirm`, and no other console/HTTP errors. Screenshots go to `docs/ops-screens/live/` with phones/tokens/keys masked in the DOM. That folder is git-ignored, because the shots still show real client and event names and main is served publicly.

The old manual-control page moved to `ops-manual.html` and is linked from the nav footer. Its buttons have not been ported yet (see "Still needs the backend").

## Components (`ui.js`)

Renderers return HTML strings, so they are testable in plain node. Behaviour is attached once by delegation in `init()`.

`Button` (variants primary/danger/ghost, sizes, press-down feedback on pointerdown) · `busy(btn, fn)` (one intent one request, width-locked spinner → ✓ / "נכשל") · `Toggle` (role=switch) · `Select` (button + listbox popover, arrows/Enter/Esc, emits `ops:change`) · `Tabs` (segmented, emits `ops:change`) · `Table` (sticky header, sticky day-part group rows, numeric columns end-aligned, tabular figures) · `mountVirtual` (virtual rows) · `Drawer` (focus trap, Esc, returns focus, slides from the inline-end) · `confirmTyped` (alertdialog, the action button stays disabled until the exact id is typed) · `toast` (aria-live) · `Skeleton` (lines/tiles/card/table) · `StatTile` (+ meter) · `Sparkline` · `Badge`/`statusDot` (status = color + glyph + word, never color alone) · `KeyHints` · `Code` (line numbers, highlighted anchor line) · formatters (`fmtN`, `fmtMoney`, `relTime`, Israel-time `fmtTime`) · tooltip via `data-tip`.

No native select, checkbox, `alert`, `confirm` or `prompt` anywhere (the smoke test greps for them).

## View-model the screens read (output of adapt.js; superseded as an API spec by docs/OPS-API-2026-11-03.md)

All `POST /api/ops/<name>`, body `{admin_key, ...stamp, ...params}`. `{ok:false, error}` is shown as an error box. 404 shows "endpoint doesn't exist yet". The list below was the pre-backend assumption; adapt.js now produces the subset the screens use from the real responses (see Integration).

- `capacity` → `days[{date,dow,no_contact,closed_reason,capacity_wa,planned_wa,capacity_calls,planned_calls,events[{token,name,planned_wa,kind}]}]` (14), `alerts[{date,kind:'wa'|'calls',over_by,msg}]`, `recommendations[{token,name,event_date,wave,send_on,planned,reason}]`.
- `balances` → `vendors[{vendor,label,amount|null,currency,low_threshold|null,topup_url,auto_topup:true|false|'unknown',as_of,source:'api'|'manual',note?,spent_month?,usage_pct?,plan?,spend_cap?}]`.
