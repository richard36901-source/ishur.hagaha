## מפת המערכת בקצרה

```
לקוח באתר ishur.io
   │ תשלום (Grow)
   ▼
Grow IPN ──► Worker (/api/grow-ipn) ──► תרחיש 1 ב-Make ──► Google Sheets
   │              │                        └─ חשבונית מורנינג (כבויה)
   │              └─ טוקן נשמר ב-KV
   ▼
דף תודה ──► /api/claim ──► קישור העלאה אישי (upload.html?t=טוקן)
   │
   ▼ העלאת קובץ + הגדרות + תמונה
Worker (/api/event) ─ קורא ומאמת את הקובץ בעצמו ─► תרחיש 2 ──► Sheets
   │
   ▼
דשבורד (dashboard.html?t=טוקן) ──► /api/status ──► תרחיש 3 (קריאה) ──► Worker מחשב ──► JSON
דף מוקד (calls.html)            ──► /api/status עם מפתח מוקד ──► תור שיחות
מנוע שליחה יומי                 ──► תרחיש 4 (כבוי, מחכה למספר ב')
```

**עיקרון החלוקה:** כל דבר שביר (ולידציה, קריאת קבצים, דדופ, חישובים)
יושב בקוד של ה-Worker בקלאודפלייר — נבדק אוטומטית. Make נשאר "כתבן
טיפש": מיפוי עמודות בלבד. לשנות איזו עמודה מקבלת מה — עורכים ב-Make.
לשנות לוגיקה — ב-`worker/`.

## תרחישי Make (תקיה 379970)

### 1 · תשלום Grow → לקוח + אירוע + חשבונית (7150277, פעיל)
- ה-Worker מקבל את ה-IPN מ-Grow, מוודא שזה תשלום חדש (דדופ לפי אסמכתא),
  מייצר טוקן, ושולח ל-Make שורה נקייה.
- Make: מוסיף שורת אירוע ← אם לקוח חדש מוסיף שורת לקוח ← מעשיר
  פרטים מהליד (לפי 9 ספרות אחרונות של הטלפון) ← חשבונית.
- **חשבונית מס-קבלה (מורנינג): בנויה אבל כבויה.** על מודול החשבונית יש
  פילטר שתמיד נכשל (`off = on`). כדי להפעיל: פותחים את התרחיש ב-Make,
  לוחצים על הפילטר שלפני "חשבונית מס-קבלה במורנינג", ומשנים את הצד
  השמאלי מ-`off` ל-`on`. סוג מסמך 320, מחיר כולל מע"מ, תשלום אשראי.

### 2 · העלאת אורחים + הגדרות אירוע (6959458, פעיל)
שלושה מסלולים לפי `event_type`:
- `guests_file` — ה-Worker כבר קרא את הקובץ והכין שורות מוכנות; Make רק
  מדביק את כולן בבת אחת לגיליון אורחים ומסמן `AR = כן` באירוע.
- `event_setup` — כותב את כל שדות הטופס לעמודות AF-AS. **המיפוי עמודה↔שדה
  נמצא במודול "כתיבת פרטי האירוע"** — שם משנים אם רוצים עמודה אחרת.
- `call_result` — תוצאת שיחה מדף המוקד: מעדכן P/V/W/X/Z/AD לפי מה
  שה-Worker חישב.

### 3 · נתוני דשבורד (6959463, פעיל)
קריאה בלבד: מחזיר את שתי הלשוניות כמו שהן. ה-Worker מסנן לפי טוקן,
מחשב סיכומים ובונה את ה-JSON שהדשבורד מציג. אין כאן שום לוגיקה לתחזק.

### 4 · מנוע שליחה יומי (7150907, **כבוי בכוונה**)
רץ כל בוקר 09:05 (כשיופעל). מוצא אירועים שהיום הוא אחד מתאריכי השליחה
שלהם, ואז לכל מסלול: שולח תבנית וואטסאפ לאורחים הרלוונטיים ומסמן את
התאריך בשורת האורח (עמידות לריצה כפולה: מי שסומן היום לא יקבל שוב).
מסלול רביעי: בוקר אחרי השליחה האחרונה, כל מי שלא ענה מסומן

   תמונת ההזמנה נמצאת בעמודה AS של האירוע).

## ה-Worker (`worker/`)

כתובת: `https://ishur-webhooks.richardtomskiy.workers.dev`

| נתיב | תפקיד |
|---|---|
| `/api/grow-ipn?k=...` | קליטת תשלום מ-Grow (מפתח ב-`/tmp/grow_key.txt` אצלך) |
| `/api/claim` | דף התודה שואל "שילמתי, לאן ממשיכים?" ומקבל את הטוקן |
| `/api/event` | קובץ אורחים (נקרא ומאומת כאן!), הגדרות אירוע + תמונה, תוצאות שיחה |
| `/api/status` | נתוני דשבורד לפי טוקן, או תור שיחות לפי מפתח מוקד |
| `/img/<token>` | מגיש את תמונת ההזמנה (נשמרת ב-KV, לא בדרייב) |

קבצים: `index.js` ניתוב ואבטחה · `parse.js` קריאת CSV/Excel · `dashboard.js`
חישובי דשבורד ותור שיחות. לשנות ולפרוס: `cd worker && npx wrangler deploy`.

**ולידציית קובץ אורחים:** עמודה A שם, B טלפון, C (רשות) כמות מוזמנים.
בדיקת magic bytes (קובץ PDF ששמו שונה ל-xlsx נחסם), נרמול טלפונים
ל-972, סינון כפולים ומספרים לא-ניידים, מקסימום 2000 שורות, 8MB.
העלאה שנייה לאותו אירוע נחסמת (409) — החלפת קובץ דרך התמיכה, בכוונה.

**סודות (wrangler secrets):** `HOOK_GROW/EVENTS/STATUS/LEADS` (כתובות
ה-hooks), `APP_KEY` (חתימת הדפדפן), `GROW_KEY` (מפתח ה-IPN),
`ADMIN_KEY` (מפתח דף המוקד). החלפה: `npx wrangler secret put <שם>`.

## דף המוקד — calls.html

`https://ishur.io/calls.html` · מפתח גישה: נשלח אליך בנפרד (נשמר במכשיר
אחרי הכניסה הראשונה, אפשר גם `?key=<מפתח>` בקישור).

מציג את כל מי שמסומן `נדרשת שיחה`, מקובץ לפי אירוע, עם תסריט שיחה מוכן
וכפתורים: **מגיע / לא מגיע / מתלבט / לא ענה / לחייג שוב**. כל לחיצה
נכתבת מיד לגיליון. "לא ענה" סופר נסיונות — אחרי 3 האורח יורד מהרשימה.

## אבחון תקלות

- **Make**: History של התרחיש ← ריצה אדומה ← הודעת השגיאה על המודול.
- **Worker**: `cd worker && npx wrangler tail` מציג בקשות חיות.
- תשובת `502 writer-failed` באתר = Make החזיר שגיאה — לבדוק את ההיסטוריה.
- **נתוני בדיקה**: כל השורות עם אסמכתא `TEST-REF-*` וטלפון `545764327`
  הן בדיקות שלנו — למחוק לפני עבודה עם לקוחות אמיתיים.
- **ishur.io חסום אצלך בבית?** הפילטר של בזק (SecuringSam) חוסם את
  הדומיין ברשת הביתית. להסיר בחסימות באפליקציית בזק. מלקוחות רגילים
  האתר נגיש.
