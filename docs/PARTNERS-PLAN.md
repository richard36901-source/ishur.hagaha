# תוכנית שותפים · החלטות ריצ׳רד 21/10/2026

## שני סוגי שותפים

| | אולם אירועים | מנהל/ת אירועים |
|---|---|---|
| דמי הצטרפות | אין. לא חד-פעמי, לא חודשי | אין |
| מה מקבל | **10% הנחה** ללקוחות שהוא סוגר (ההנחה לזוג) | **20% עמלה** על כל סגירה (מהמחיר ששולם) |
| מי משלם ל-ishur | הזוג (במחיר אחרי 10%) או האולם, לפי הסדר שלהם | הזוג או מנהל האירוע |
| דף שותף | רשימת האירועים שסגר, קישור ללוח של כל זוג | רשימת סגירות + עמלה לכל עסקה + סה"כ עמלה שנצברה / שולמה |
| לוח הבקרה של הזוג | שם החתן והכלה, **בלי** סכומים, בלי תשלומים, **בלי** חשבונית | אותו דבר |
| חשבונית | לא מוצגת לזוג | לא מוצגת לזוג |

## מה בונים (סדר)

1. **מודל**: `partner:<code>` ב-KV = { code, kind: 'venue'|'planner', name, phone, email, logo, rate: 0.10|0.20, at }.
   אירוע שנסגר דרך שותף: `evpartner:<token>` = { code, kind, paid, discount|commission, at }.
2. **זרימת רכישה**: `?p=KODE` באתר/בפופאפ → מחיר אחרי 10% (אולם) או מלא (מנהל אירועים) → Make מייצר קישור במחיר הנכון עם cField=partner:KODE → IPN כותב `evpartner` + מחשב עמלה.
3. **דף שותף** `partner.html?p=KODE`: OTP לטלפון השותף (מנגנון ה-OTP הקיים), רשימת אירועים, לכל אירוע: שם הזוג, תאריך, מצב אישורים, קישור ללוח; למנהל אירועים גם עמלה לעסקה וסה"כ.
4. **לוח הזוג במצב שותף**: `dashboard.html` מסתיר: מחירים בתוספות? (לא, תוספות נשארות, הזוג יכול לקנות), כרטיס חשבונית, "שדרוג" מציג מחיר הפרש רגיל. מציג "באדיבות {שם האולם}" + לוגו.
5. **הצטרפות**: `partners.html` נחיתה + טופס → ליד "שותף" לסלאק + מאנדיי → ריצ׳רד מאשר → קוד.
6. **תשלום עמלות** למנהלי אירועים: ידני בסוף חודש מדוח בדף השותף (`/api/partner-report`). שלב 2: אוטומטי.

## תנאי מעבר (verify-loop)

- רכישה עם `?p=VENUE1` יוצרת קישור Grow במחיר 90% מהמחירון, ה-IPN כותב `evpartner` עם discount.
- רכישה עם `?p=PLAN1` יוצרת קישור במחיר מלא, `evpartner` עם commission = 20% מהסכום.
- `partner.html?p=PLAN1` אחרי OTP מציג את האירוע עם העמלה הנכונה.
- `dashboard.html?t=<token של אירוע שותף>` לא מציג כרטיס חשבונית ולא סכומי תשלום.
