## Endpoints (worker/ops-calls.js, routed in ops.js handleOps; admin key as other /api/ops/*)
- GET `/api/ops/calls?day=|from=&to=|week=1&event=&outcome=a,b&number=&agent=&cursor=&limit=`: timeline from audit kind `call`. Gives one outcome key per call (coming/not_coming/maybe/callback/voicemail/no_answer/answered/failed/do_not_call), the attempt # per guest within the range, a ₪ cost split and a `costs` rollup.
- GET `/api/ops/call?id=&day=`: Retell transcript turns (falls back to the audit transcript), AI summary, analysis, and the recording as a signed `/rec/<id>?e=&s=` link that expires after 1 day.
- GET `/api/ops/call-rounds`: per-event cards: queued / remaining today / capped / dialed / answered / cost, plus `why` reasons (not-configured, paused, off switches, holiday, window, hold, stopped, plan, daily-cap, event-passed, all-capped, done-today, empty, no-capacity).
- POST `/api/ops/call-round {token, action:start|stop, confirm, extra?, reason?}`: you type confirm = the first 8 characters of the token. stop writes `callstop:<token>`, and runShirDispatch now skips it. start deletes it. With extra:true it writes `callround:<token>` for today.
- GET/POST `/api/ops/manual-calls`: lists the "נדרשת שיחה" queue with notes (`mcnote:<gid>`). `{action:'note'}` saves a note. `{action:'done', outcome}` writes through the same call_result writer as /api/event.
- GET `/api/ops/shir`: read only. Prompt version/history, begin_message, model, voice settings. Edit and rollback go through the existing POST `/api/voice-prompt`.
- GET `/api/ops/call-costs?from&to`. `buildCallCosts` and `callCostRollup` are re-exported from ops.js for the finance screen.

## Costs
Retell = audit `cost` (₪, combined_cost × 3.7). Nothing records Telnyx per call, so the Telnyx figure is an estimate: billed minutes × `TELNYX_ILS_PER_MIN` (or `TELNYX_USD_PER_MIN` × 3.7). When neither is set it shows null, not 0.

## UI
`assets/ops/lazy/calls.js` has these tabs: ציר / סבבים / שיחות ידניות / שיר / עלויות. `screens/calls.js` is a shim that keeps tiles()/view() and calls import() on the lazy module. app.js is unchanged. The screen's CSS is injected by the lazy module. Fixtures in `fixtures/ops/{calls,call,call-rounds,manual-calls,shir}.json` were generated by running the real handlers on masked seed data.
